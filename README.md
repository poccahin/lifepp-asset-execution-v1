`[A]` This implementation supports validation only through `PROPOSAL_ONLY`. The current operational state remains `DISARMED` because real protocol finality, A4 finality, a transaction-specific permit, cryptographically verified 3-of-4 approval, and independent release/executor authority do not exist here.

`[D]` A transaction gate binds one exact canonical message root to one policy root, two rooted RPC simulations from distinct control domains, a PoCC FINALIZED certificate, a closed challenge, responsibility coverage, the verified 3-of-4 treasury configuration, a rooted timelock, an expiring transaction-specific permit with distinct roster-bound approval references, and a second fresh dual-RPC pre-execution simulation.

`[SIM]` `evidence/simulated-proposal-package.json` exercises every proposal check deterministically. Its protocol/A4/PoCC/approval evidence is explicitly simulated, so all live checks remain false and it can produce only a rooted unsigned proposal. It is not an `AssetExecutionPermit`, signature, transaction authorization, or receipt.

`[RET]` The receipt constructor accepts only externally observed `LIVE_VERIFIED` finalized state with a verified permit, treasury approval, two initial and two pre-execution simulation roots, and an independent executor attestation. No receipt is generated by the current Shadow evidence build.
